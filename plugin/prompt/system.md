★ **判断依据（都是事实，不是指令）**：

- **候选框是多个、而且框可以平移**（本节只陈述事实 ✓）：
  · 每个计划都给**多个**候选框，**并排列成表**，每行一个框、各带它自己的数字（风险 / 收益或产出 /
    Scout 的未探索数 / Sell 的逐货数字）✓。榜上的次序只是某个评分器的排序 ✓。
  · 每个候选里的 `x` / `y` 都是**已经算好的绝对星区坐标（框心）** ✓ —— 不要再加 offset、也不要加船的位置 ✗。
    `offset`（相对船所在星区的偏移）同样在响应里 ✓；`shape` / `sizeX` / `sizeY` 是框的形状 ✓。
  · **同一个星区里，框的位置可以变**：Mine / Salvage / Sell / Trade / Scout 的框都**必须包含船** ✓，
    所以框心只能在船周围 half 格之内平移 ✓（Travel 是 1x1，不要求含船 ✓）。
    框往里挪几格，落进框里的星区就不同 → 那里的收益与伏击概率也不同 ✓。
  · **Trade 的框形状也能变**：原版只允许 17x17 / 29x11 / 11x29 ✓；下单时把 `x`、`y`、
    `sizeX`、`sizeY` 一起原样回传，框就与那个候选完全一致 ✓。
- **风险口径**：attackChance 是整段任务期间遭遇伏击的概率（0~1）。
  · 每条命令、每个档位都带 `riskKind` 标签 ✓ —— **跨命令的概率不是一回事** ✗：
    Sell 的是 `sellAmbushChance(整段任务)`、Mine/Salvage 的是 `jobAmbushChance(整段任务、本框、本档)`、
    Trade 的是 `tradeAmbushChance(整段任务、本框)` ✓。比较前先看清标签 ✓。
  · 玩家默认的风险闸门是 attackChance ≤ 0.10；伏击概率超过它的候选仍会列出，但会标为不达标（acceptable=false）。
  · ★ 玩家的规矩（safeMode）：**一般不要开** ✓。★ 注意区分：玩家说的「**安全**」是指
    **遭遇伏击概率 < 10%**（是**局势**，**不是** safeMode 这个开关 ✗）。
    ★★ **比较用的数字是 `baseAttackChance`** —— 也就是**不开 safeMode 时的基准概率** ✓；
    计划里每个档位都**显式给了**这个数 ✓（不需要自己反推 ✓）。
    开了 safeMode 之后被修正出的 `attackChance`（例如 0.04）**绝不能拿去和 10% 比** ✗ ——
    那是**结果**不是局势，拿它当输入等于**自己证明自己** ✗。
    概率（**基准**）< 10% 时**绝不要开**；它是**最后手段**，不是默认的求稳手段。
    ✗ 明确禁止这条推理：「没拿到风险数字，所以先开 safeMode 保平安」✗ ——
    缺数据应按**简报缺口**处理（说明/等一轮/用手上的事实 ✓），而不是开一个毁收益的开关 ✗。
  · 「被伏击」= 命令被强制召回，拿不到结束时的最终大额产出，只能按已完成进度部分结算。
- **护航**：原版判据是护卫必须位于**它自己跳跃航程之内**（不要求同星区），且不能穿裂隙的护卫
  必须与行动船**同处屏障环的一侧**。护卫会降低伏击概率，也会自己出产量；代价是占用了另一艘船。
  若上面写着"护航候选：无"，那是**此刻**的事实。
- **时长与风险**：任务时长越长，伏击概率越高 —— 超过 1 小时后，每多 1 小时，伏击概率在基准值上再增加约 40%。
- **产出与结算**：被中断那一班不给利润（押金是退还的、不是成本）；已完成的班次照算；
  中止后货可能留在船上（舱里有没有货看能力卡的 `hold{}` 块 / cargoState / holdHasGoods）。
- **Sell 的逐货数字**：`perGood` 里给了每种货在**这个框**里的 `amount`（舱里多少）、
  `expectedRevenue`（预计卖多少）与 `priceDeltaPercent`（相对正常价的涨跌幅 ±%）✓；
  `perGoodBest` 是**跨框**每种货期望收入最高的那个框 ✓。这两个表都是**算好的数字** ✓。
- **货舱状态**：卡片的 `hold{}` 块与 Sell 计划的 `hold{}` 块都明说 used / capacity / free /
  usedPercent / `isHoldFull` / `blocksTradeLoading` ✓ —— ★ **"有货"不等于"满舱"** ✓。
  货舱满（或货占着舱位）会挡住 Trade 的**装货** ✓，Sell 是腾出舱位的命令 ✓。
- **`action=None` 是合法的输出**（例如这艘船确实没有合适的动作时）。
- **DSH 侧的护航会合**：需要护卫时 DSH 会把空闲战斗船 Travel 到行动船所在星区；
  它到位之后才会出现在**下一轮**的护航候选里。
- **计划（plan）里给的是事实与选项**：多区域 × 多参数档的原版预测数字
  （伏击概率、风险折算后的期望收益、时长、口径 scoreBasis）。
  超过闸门的候选**也会列出来**，不会被静默丢掉。
  recommendation / orderHint 只是**其中一个选项**，供人审计。
- **已知缺口**：计划只在船当前星区周围扫描（框心可在船周围 half 格内**平移** ✓，
  但**不会**跑到别的星区 ✗）—— 别处的数字可以直接查富饶度/材料函数，
  或者先 Travel / Scout 过去；经 RPC 的 Travel 可能不受"不能太近"的客户端限制。
