# 接口原子化（Interface Atomicity）—— 工程规范

> 上一级：仓库根 [`AGENTS.md`](../../AGENTS.md)（工程入口索引）。
> ★ 本文件是**接口设计规范** ✗✓ —— 只规定「接口该怎么拆」；**决策过程本身不写在这里** ✗（主人明确说了 ✓）。

## ★ 唯一原则（主人原话，逐字）

> 「你直接把接口原子化这件事完成。功能要拆到最散，包括查询舰船的功能，你也不要一次性把
> 全部舰船状态查回来，你应该做的是查一个列表，看列表里有什么船，决定先处理哪条船就查
> 哪条船的信息，拿到船信息后再拿来判断这船能干嘛，然后再做后续的事。」

落到一条规矩：**游戏只提供「一次做一件最小的事」的原子接口；策略与判断永远属于调用方（决策者）。**

## 判据（一个接口算不算原子）

一个原子接口必须**同时**满足下面全部五条：

1. **一次一件小事** ✗✓：一个接口只做一件最小的事。查船就查船、算一个框就算一个框、下一条命令就下一条命令。
2. **不做策略** ✗：不自己决定「扫哪些框 / 选哪个 / 给不给建议」—— 那是调用方的活。
3. **不做排序推荐** ✗：不跨对象排序、不产 `recommendation` / `orderHint` / `riskWarning`。
4. **不做跨对象聚合** ✗：不把「全部舰船状态」「一个框 × 全部商品」「全部计划」打包成一次返回。
5. **便宜、可预测** ✗✓：单次耗时与体积**有界且量级已知**，调用方能预测「查这一下花多少」。

**违反任何一条 = 不是原子接口** ✗，要么拆、要么标 legacy、要么废弃。

## 正反例

| | 反例（**禁** ✗） | 正例（**要** ✓） |
|---|---|---|
| 查舰船 | 一次返回**全部舰船完整状态**（货舱明细 + 深度采样 + 逐动作说明 + 预测） | ① `list` 只给索引级（name/busy/hasCaptain/sector）→ ② 挑一条 → ③ `ship` 查**那一条** |
| 算计划 | 一次**扫 67 框** + 排序 + 给推荐（`tradePlan`/`jobPlan` 等 legacy 计划） | `predict`：**一个框 + 一个动作 + 参数 → 这一框的数字**（单框 / 批量 N≤24，N 只算 N 框） |
| 发命令 | `order` 自动选框 + 自动补参数 + 自动挑路线/兜底预付金 | `order`：**一艘船 + 一个动作 + 那一个动作的最小参数**（缺了就明确报错，绝不自己补） |
| 取路线 | 把路线 + 排序 + 推荐 + 预付金建议一次给全 | `tradeRoutes`：**某个框内**的路线 + 逐货数字（不排序、不推荐） |

组合顺序（正例链）：**`list` → `ship` → `goal`/`sectorFacts` → `tradeRoutes`/`predict` → `order`** ——
每一步只取「下一步要做判断」需要的那一块，取到再走下一步。

## 发命令接口的原子化要求（专条）

- `order` = **一艘船 + 一个动作 + 那个动作的最小参数**，仅此而已。
- **不自动选框** ✗：框（`x`/`y` + `size` 或 `sizeX`/`sizeY`）必须显式给，没给就报 `NO_POSITION`/`BAD_REQUEST`。
- **不自动加参数** ✗：Trade 的 `goodName`/`deposit` 必须显式给，没给就报 `BAD_REQUEST`，绝不自动挑/兜底。
- **不自动退避** ✗：不再「同步跑一遍区域分析去校验路线并自动改选」—— 路线对不对由游戏侧自己校验并原样报回。
- ★ **但回执要带风险**（2026-10-17 主人要求 ✓✓）：`order` 会为**这一单**算**一次**预测（口径 = `predict`，
  **同一份代码**），结果只进回执 `risk` 与 trace 流水 —— **绝不**用它改选/补参/退避 ✓✓。
  这也正是「算一次」的意义：`run` 恰好 1 次、参数与调用方给的一模一样 ✗✓（harness `_order_risk_selftest.lua` ✓）。
- 执行类保持**单件**：`recall`（单船召回）、`escort`（单次会合）、`setGoal`（单船目标），都不跨对象复合。

## 策略与判断永远属于调用方（决策者）

- 游戏**只给事实与算好的数字** ✓；「扫哪些框、怎么比、选哪个、下不下单」**全部由调用方**决定 ✗✓。
- 原子接口**不产结论** ✗：不产「该选哪个框」「该不该走」「推荐第一行」。
- 决策过程（先查什么、再查什么、怎么拍板）是**调用方的流程**，不是接口的职责 —— 也因此**不写进接口文档** ✗✓。

## 与现状的对照（legacy / 原子边界）

- **原子（已是/已落地）**：`list`、`ship`、`goal`、`sectorFacts`、`predict`、`tradeRoutes`、`order`（原子化后）、`recall`、`escort`、`setGoal`。
- **legacy（降级为显式可选，永不作默认）**：`tradePlan` / `minePlan` / `salvagePlan` / `sellPlan` / `scoutPlan` / `jobPlan` —— 它们自己在游戏侧扫框 + 排序 + 推荐 ✗，只作便利口。
- **废弃**：`orderSchema`（本就 `NOT_IMPLEMENTED`，已改 `DEPRECATED`）。
- **单发路径专属**：`dossier` —— 只给「无工具、读不了文件」的单发调用兜底 ✓。★ **2026-10-24 起它只读卡片/目标**（
  `plans` 恒为空数组 + 明说「无计划（已移除预扫描）」✓）：游戏侧**不再**替它扫那 6 个计划 ✓，
  插件侧也**不再预取**任何一个 legacy 计划 ✗ —— 单发兜底拿不到框就老实给 `None` ✓；
  要真数据的那条路由**决策者自己点名** `predict`（≤24 框）/ `tradeRoutes` / `tradeEvaluate` ✓✓。

## 落地检查（工程自检守这些）

- `list` 响应**不含**每船完整状态/货舱明细/预测；`ship` 只查一艘。
- `predict` 单框只算一框、批量 N 只算 N 框；非法框（不含船）明确报错 `SHIP_NOT_IN_AREA`
  （★ 唯一例外：**Travel** 的框是 1×1 目的地，原版 `travelcommand.lua:472` 就不要求船在内 ✓）。
- `predict` 的口径与旧计划路径**逐字一致**（复用同一批内部函数，不重写预测逻辑）。
- `order` 不含复合/自动补全行为（自检断言：缺框 → `NO_POSITION`、缺尺寸 → `BAD_REQUEST`、Trade 缺 goodName/deposit → `BAD_REQUEST`）；
  ★ 它**会**为回执算一次预测（`run` 恰好 1 次、不改单 ✓），且算不出来时 `risk.known=false` + 原因、
  **绝不填 0** ✓✓（`_order_risk_selftest.lua`）。
- 工具说明（`fleet_query`/`fleet_order`）把原子接口列为默认，把 legacy 计划标为 legacy。

## ★★★ 性能硬闸（Hard Gates）—— 不许再犯「超高消耗操作」

> 主人原话（2026-10-24）：「注意不要再加之前那种超高消耗的操作了」✓。
> ★ 这不是一次性要求 ✗ —— 本节把它变成**会自己红的机制** ✓✓：
> 规矩在这节 ✓、机器可读的名单在 [`interface-whitelist.txt`](interface-whitelist.txt) ✓、
> 断言在 `plugin/dsh/test/what-whitelist.mjs` + `native/harness/_what_whitelist_selftest.lua` ✓✓，
> 探针在 [`perf.lua`](../../data/scripts/lib/copilot/perf.lua) ✓。
> ★ 加接口先过这五道闸 ✗✓；过不了就别加 ✗。

### G1 接口不许自己选框 / 不许排序 / 不许给推荐

- 框（`x`/`y` + `size`，或 `sizeX`/`sizeY`）与动作（`action`）**必须由调用方点名** ✓✓；
  接口没收到就**报错**（`NO_POSITION` / `BAD_REQUEST`），绝不自己补 ✗。
- 接口**不产** `recommendation` / `orderHint` / `best` / 「第一行」✗；比哪几个框、选哪个，都是调用方的事 ✓。
- 这条既是本文 §判据 第 2、3 条的复述，也是**硬闸**：违反的实现无处可藏 ✓（见 G2 的断言）。

### G2 单次 RPC 里不许出现 O(框数 × 星区数) 的隐式扫描

- 一次 RPC 里**不许**「自己决定扫 N 个框、每个框再算一遍星区/路线」✗；
  要扫就必须**由参数给出框**，且框数有硬上限（`predict` ≤24 框、`tradeEvaluate` ≤6 框 ✓✓）。
- 尤其不许「为了给一个数字，顺手把整张舰队/整个星区/全部计划都算一遍」✗ —— 那正是下文反例的死法 ✓。
- 接口白名单是**唯一真相**：[`interface-whitelist.txt`](interface-whitelist.txt)
  （`[atomic]` 可被插件调用 / `[legacy]` 只许留在游戏侧 / `[deprecated]` 只许返回 `DEPRECATED`）✓✓。
  新 `what` 不在名单里 → 测试**红** ✓。

### G3 任何新查询必须报出预估扫描规模

- 新增 `what` 必须同时写清：**一次最多几框 / 几实体 / 几次原版高代价调用** ✓。
- 规模上限写进接口表：[`fleet-ops-manual.md`](../game/ops/fleet-ops-manual.md) §2 的「扫描规模上限」✓✓。
- 写不出上限（说不清最坏情况）= 这个接口不该存在 ✗。

### G4 单次 RPC > 100 ms 就必须有探针

- 超过 **100 ms** 的 RPC 必须在 `moddata/copilot/perf.log` 留一行：**名字 + 毫秒** ✓
  （实现：`net/rpc.lua` 的 `onRequest` 在 handler 外面包计时 ✓；阈值 = `perf.lua` 的 `QUERY_THRESHOLD_MS`，可调 ✓）。
- 周期任务同样打点：`ops.updateServer` / `fleet.scan` / `net.pump` ✓✓。
- **仍不刷屏** ✗：每条名字最多 30 秒一行（`perf.lua` 的 `MIN_INTERVAL`，按名字节流 ✓），平时一条都不写 ✓。

### G5 单发兜底路径只许只读轻事实，不许跑计划

- 没有工具、读不了文件的那条单发路径（`dossier`）只许拿 `list` / `ship{brief:true}` / `goal`
  这类**有界的只读轻事实** ✓；任何名字含 `Plan` 的 `what` 都不许出现 ✗✓。
- 断言：`plugin/dsh/test/single-shot-no-plans.mjs` 用 **`/plan/i` 正则**卡「任何名字含 Plan 的 what」✓✓。

### 反例清单（已删的那批 + 实测数字，别再复活 ✗）

| 接口 | 实测（真机 `rpc_trace.log` / `perf.log`） | 病根 |
|---|---|---|
| `tradePlan` | **173 次 × 均 10.5 s，最高 21 s** ✗ | 游戏主循环里同步扫 67+ 框 × 多商品 + 排序 + 推荐 |
| `dossier`（旧版） | **22 ~ 31 s** ✗ | 一次把 6 个计划全扫一遍（2026-10-24 已改成只读卡片/目标 ✓） |
| `sellPlan` | **均 8 s** ✗ | 多区域分析 × 逐货搜索 |
| `jobPlan` | **71 框 / 828 ms**（最坏 884 ms）✗ | 粗扫 71 框 × 参数 × 层级加权 |
| `scoutPlan` | **1321 ms** ✗ | 同一形态的大扫描 |
| 单发预取 legacy 计划 | 每次决策**额外 10 ~ 30 s** ✗ | 兜底路径替决策者做策略（已移除 ✓） |

### 正确替代（照这个组合，不许回头 ✗）

```
list  →  ship{brief:true}  →  predict(≤24 框) / tradeRoutes / tradeEvaluate(≤6 框)  →  order
```

- 查哪艘船 = 调用方点名 ✓；比哪几个框 = 调用方点名 ✓；选哪个 = 调用方拍板 ✓。
- `predict` 的口径与旧计划**逐字一致**（复用同一批内部函数 ✓）—— 便宜不等于降级 ✓✓。
